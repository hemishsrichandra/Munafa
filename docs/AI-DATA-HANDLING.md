# AI data handling and trust boundary

Version 1 · 30 October 2026. No production privacy/security certification is claimed.

- Secrets stay server-side. Requests use the configured Sarvam key and fixed official base, bounded timeouts and role/rate checks. Models receive only explicitly submitted text/image/audio, not a store-wide customer/supplier database. The help path uses no remote model at all.
- Invoice bytes/text remain original purchase documents in PostgreSQL with hashes and immutable extraction revisions. Extraction may propose printed billed fields; actual received quantity, delivery/pricing confirmation, inventory events, payment truth, promises and recovery application require merchant workflows and server approval. No model tool has a financial write capability.
- Strict versioned raw schema rejects authority fields and unknown keys. Document content/metadata/filenames are untrusted; no uploaded content becomes a system instruction, retrieval source or URL to fetch. Text-layer PDF parsing is bounded in an isolated helper. Missing confidence/coordinates stay unknown; the UI shows review requirements. These controls reduce exposure but do not prove immunity to all prompt injection. Merchant review and deterministic checks remain mandatory.
- Each extraction makes at most one model attempt per user request. After two invalid structured outputs for the same store/source SHA-256, further automated extraction stops. A PostgreSQL advisory lock and persisted telemetry enforce the invalid-output budget, including across request failures. No API-key/network outage consumes the invalid-schema budget. Manual entry remains available. The telemetry transaction is deliberately independent of the business transaction so a rejected HTTP request cannot erase the budget.
- `ai_runs` stores only actor/store, purpose, input hash, provider/model, status, latency, allow-listed usage counts and unknown billed cost. It contains no document, prompt, transcript, phone, secret or response. The read-only 30-day usage summary is store scoped; valid output is not task acceptance. Telemetry currently has no automatic purge, so retention continues until an explicit owner-approved maintenance policy is implemented. The invalid-attempt budget lasts while these records exist.
- Browser recording begins only on a user click after consent and browser microphone permission, shows state/stop, is bounded to 20 seconds/2 MB, releases tracks on stop/cancel/unmount, and uses memory only. The server validates MIME/signature, sends transient bytes for STT, then discards them; it creates no audio attachment or IndexedDB audio record. Transport/framework temporary buffers may exist for the request. Transcript is editable UI text and is not saved unless the merchant explicitly uses a separate draft workflow. Native microphone permission is not added; Android uses touch/text.
- Local audio disposal is **not provider-side zero retention**. The official [Sarvam retention guide](https://docs.sarvam.ai/api/platform/data-retention), checked 30 October 2026, says an owner must configure workspace retention; without a configured period, data may be retained indefinitely. It describes a zero-retention option for Model APIs, subject to product rules. Verify actual workspace/product settings and signed terms before real inputs. This app has not verified those account settings, training use or processing-region commitments.
- Translation is a draft, with source visible and numeric/reference checks. Numeric matching cannot establish semantic fidelity. A mismatch disables the translated share/copy route; otherwise explicit merchant review is required. Existing supplier sharing remains a manual handoff, not a delivery receipt.
- Help retrieves only the repository-curated versioned implementation guide and a dated official technical excerpt. These are not Paytm business-policy approval or an endorsed fee schedule. Source IDs, sections, versions and review expiry are returned. Missing/stale/contradictory or unsupported policy/outcome questions abstain and offer the official account-support path. No arbitrary URL retrieval, user-uploaded corpus or cross-merchant search is allowed. Read/draft tools are allow-listed, purpose typed and principal scoped; follow-up drafting rechecks messaging permission and source approval. Draft text cannot send or execute.
- Browser storage/offline threat model remains in SYNC-PROTOCOL.md. No device-level encryption or guaranteed recovery after eviction is claimed. Public bundled product help is cacheable; private AI responses and API data are excluded from service-worker caching. Logs should remain request metadata only; do not enable provider request/response debug logging with real merchant inputs.
