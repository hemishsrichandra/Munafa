# Paytm integration gate — checked 30 October 2026

| Capability                                       | Status                                      | Evidence required to enable                                                                                    |
| ------------------------------------------------ | ------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Fixture payment / refund / reversal observations | Working synthetic adapter, demo stores only | Local tests, never Paytm transactions                                                                          |
| Settlement component reconciliation              | Working deterministic read model            | Complete recorded components; no fee rate assumptions                                                          |
| Live polling / webhooks                          | Disabled                                    | Authorised merchant access, official supported environment, verified request/signature contract, real E2E test |
| Statement upload / bank receipt verification     | Not implemented                             | Document provenance, parsing validation and explicit review; actual bank evidence                              |

The official [Settlement Detail API](https://www.paytmpayments.com/docs/api/settlement-detail-api/) and [Settlement API](https://www.paytmpayments.com/docs/api/settlement-api/) describe settlement fields, including commission, GST and dates, and state that these APIs are not hosted on staging. Public documentation is not account authorisation. No URL/signature/webhook contract is guessed in this implementation.

Before enabling LIVE: obtain written merchant authorisation and correct API product entitlement; verify credentials/environment directly with Paytm; pin request, money-unit, pagination, timezone, cutoff and signature schemas from the supplied contract; add fixture redaction and contract tests; verify replay protection/authenticity before accepting any bytes as events; map provider source/event/transaction IDs; test duplicate/out-of-order updates, multiple partial refunds, reversals, adjustments, missing fields, status corrections, rate limits and reconciliation with bank evidence. Define secret rotation, least privilege, retention and incident procedures. A successful authorised end-to-end test is mandatory before claiming live access.

The internal ingestion service accepts only `fixture` + `demo`, only for an authenticated demo-store administrator. There is no public webhook ingestion endpoint. `DisabledLive.verify_webhook` always rejects. No claim of real webhook validation is made. Immutable observations retain schema-versioned fixture provenance and canonical SHA-256. Future live raw sources need a private encrypted store and redaction/retention policy; raw provider PII is not currently collected.

Payment, refund and reversal **logical event IDs** distinguish partial refunds from status observations. Latest event time wins only for provider observation status, never financial ledger truth; conflicting equal-time observations require review. Batch source IDs are immutable; corrected provider snapshots must carry new revision IDs. Each settlement line explicitly records gross, commission, GST, refund, reversal and signed adjustment. Unknown is not zero. Net = gross − commission − GST − refund − reversal + adjustment. Difference = recorded payout − calculated net. Reasons identify known fields or review candidates; they never assert missing money. Payout references are not independently verified bank receipt.

All tables are principal-store scoped, with unique source IDs per store/mode/provider, composite store/mode foreign keys and append-only triggers. Demo and live use separate mandatory discriminators, adapter gates and API mode filters; live ingestion is disabled. An isolated demo store cannot present these fixtures as live. No customer debt or SKU sale is inferred from payments. No CSV payment export is supplied in this batch; existing supplier export remains separate.
